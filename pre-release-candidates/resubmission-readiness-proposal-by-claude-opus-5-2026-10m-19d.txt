DO NOT SPEND TIME ON THESE
================================================================================

"blocks failed: 11" is not eleven problems. Two are real (06 and 12); the rest
are environment, warnings-only, a tool misconfiguration, or a bug in the gate
script itself. Specifically:

  block 19  "NOT RUN: block 19 has no command" -> exit 1 on every run. While
            that block is empty, "blocks failed" can never reach 0, so the
            headline number is not a release signal.

  block 08  0 ERRORS, 110 warnings -- with every suppression annotation renamed
            so none can take effect. That is the strongest static result in the
            run: it proves the suppressions are not load-bearing. It exits 1
            only because the warning count is above zero.

  block 05  0 errors, 50 warnings. Exit 2 means "some findings are
            auto-fixable", not "worse than exit 1". PHPCS Runner.php:141-150
            returns errors plus warnings; the 1-vs-2 split is fixability, not
            severity.

  block 06  5 errors, under the bare WordPress standard. The same tree is 0
            errors under the project ruleset. The gap is the declared
            customSanitizingFunctions: bare WPCS cannot know a FLOSC sanitizer
            sanitizes. Let Plugin Check tell you whether these matter; do not
            pre-fix them, and do not resolve them with phpcs:ignore.

  block 14  746 PHPStan errors. 342 of them are two lines of configuration, not
            code. testing-environment/phpstan.neon.dist uses excludePaths:
            analyse: for */tests/*, which stops those files being reported on but
            not being scanned for symbols -- so test stubs shadow the real ones.
            The arities match exactly: the WP_Error stub at
            tests/test_starter_pack_install.php:39 takes 2 parameters and PHPStan
            reports "invoked with 3, 0-2 required" 221 times; the real
            WP_Error::__construct takes 3. Same mechanism for esc_url_raw,
            add_query_arg, check_admin_referer, current_user_can,
            wp_remote_retrieve_response_code, wp_upload_dir, FLOSC_Filesystem
            (20 errors -- all 20 methods exist in
            includes/filesystem/class-flosc-filesystem.php) and
            FLOSC_Site_Content_Index. A further 21 are FLOSC_PLUGIN_URL and
            FLOSC_DEBUG, both defined at flosc.php:45 and :47, which PHPStan
            needs in bootstrapFiles. PHPStan is not a WordPress.org review
            criterion. Fix the config after you resubmit, not before.

  block 18  Mostly its own extractor keeping trailing PHP syntax, so it curls
            strings like https://api-m.paypal.com' and https://console.x.ai\n2.
            The rest are POST-only endpoints correctly answering 401/404 to an
            unauthenticated GET, and intentional placeholders (yoursite.com).
            Worth knowing: https://dainis.net/donate/ is not among its 156 URLs.
            The one URL the reviewer flagged is the one it never tests.

  block 21  Playground fatals inside plugin-check's own PHPCS before FLOSC is
            analysed: fopen(php://stdin) returns false in Playground's PHP, then
