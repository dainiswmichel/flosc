Devnotes

  • Use Michel Date Stamp Innovation format for notes and references: YYYY-MMm-DDd (optionally with time).
  • Keep changes scoped to active plugin paths and avoid broad archive-wide search noise when diagnosing issues.
  • For UI refactors with repeated render paths, keep static markup and JS row builders synchronized to prevent drift.
  • After deployment, verify local/live parity with checksum comparison for each touched file.
  • Document any item that cannot be runtime-verified locally and mark required manual test coverage explicitly.
