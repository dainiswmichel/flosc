FLOSC v79 — Regression Accounting

Every executable change v78 made, what could break, and whether that has actually been tested. Plugin version 8.0.0 throughout. Candidate counter v78 → v79.

The standard this document exists to satisfy

A static-analysis PASS is not a completed repair if the repair changes executable behavior and the affected behavior has not been regression-tested.

What is established: WordPress.Security.NonceVerification reports 0 findings across 218 files, phpcs exit 0, measured on the Captain's machine.

What is not established by that: that settings save, IVR actions work, audio plays, OAuth completes, magic links authenticate, or navigation behaves. Those are separate gates and most of them are still open.

There is no WordPress, no phpcs, no wp-env and no browser in the container this candidate was built in. Every runtime row below is therefore NOT YET EXECUTED, and says so.

1. Defects found by this audit

EXECUTED — FAIL   R-1 · Site Index notices stopped rendering

Introduced by v78. Found by static trace, fixed in v79.

FieldDetail
Beforeadmin/ai-configuration.php:37 — $flosc_get = $GLOBALS['flosc_get'] ?: wp_unslash($_GET). Lines 2957–2958 read site_index_action and site_index_error from it.
Changedv78 replaced the fallback with array() to remove a bulk superglobal read.
WhyThe bulk wp_unslash($_GET) carried a NonceVerification.Recommended suppression.
What depends on itThe admin notice after every Site Index action on the AI tab: Rebuild, Exclude post, Include post, Save keywords, Reindex one — and all five error paths.
What broke$GLOBALS['flosc_get'] is never written anywhere in the plugin (verified across every candidate commit). So the fallback is always taken, so both reads became permanently empty.
FLOSC_Site_Content_Index::redirect_ai() carries the outcome in the query string on all ten paths. set_transient() runs on exactly one — the successful full rebuild, at line 1947. The other nine had no other carrier.
Net effect: nine of ten Site Index outcomes silently displayed nothing. The action still ran and still wrote; only the confirmation vanished — which is the failure mode that makes an admin click a second time.
Fix in v79Both values sourced through flosc_nav_param(). No bulk superglobal read returns, no suppression added. The dead $flosc_get indirection for view is gone too — its isset() was permanently false.
Test that proves itT-AI-2 below. NOT YET EXECUTED.

EXECUTED — FAIL   R-2 · Knowledge Base tab could not read its own URL

Pre-existing — not v78. Present in every candidate commit in this repository (3c15b22 through 7a720c4, checked individually). Fixed in v79 because it is the identical defect and was found by the same trace.

FieldDetail
Beforeadmin/knowledge-base.php:15 read view, kb_edit and kb_id from $GLOBALS['flosc_get'], fallback array().
What brokeSame root cause as R-1: that global is never written. All three reads were permanently empty, so the tab could not see ?view, ?kb_edit or ?kb_id — the entire edit-a-knowledge-base-by-URL route.

4. Test procedures

Smallest reproducible steps, for a local WordPress with the v79 zip installed and WP_DEBUG plus WP_DEBUG_LOG on. A PHP notice in the log counts as a failure even when the screen looks right.

Settings

  • T-SET-1 — FLOSC → Settings, change any field on the Identity tab, Save Settings. Expect: saved confirmation, value persists after reload. Fail: "Are you sure you want to do this?" (= nonce mismatch) or a blank page.
  • T-SET-2 — Same, but Save from the AI tab's "Save AI Settings" button. This button lives outside the form and binds by form= attribute; it is the one most likely to break.
  • T-SET-3 — Trajectories tab → create a trajectory, then toggle one on/off. Two separate nonce fields, both in the route table.
  • T-SET-4 — Concierge tab → create a concierge post.
  • T-SET-5 — After each save above, confirm the page returns to the same tab, not to Identity. This is the flosc_forced_tab mechanism.

IVR

  • T-IVR-1 — IVR Messages tab → edit a message → Save. Confirm the text persists.
  • T-IVR-2 — Upload an IVR file.
  • T-IVR-3 — Duplicate a file, then delete the duplicate.
  • T-IVR-4 — Export IVR; confirm a file downloads.
  • T-IVR-5 — Preview import, then Confirm import.
  • T-IVR-6 — Force resync, and Clear IVR DB on a throwaway flow.
  • T-IVR-7 / T-IVR-8 — Flow tab → Portability: create a kit, then apply one.

Any of these doing nothing at all (no notice, no change, no error) is the signature of a submit key missing from the dispatcher table. Any of them showing "Are you sure you want to do this?" is the signature of a wrong nonce action.

Audio

  • T-AUD-1 — Play a member audio file from the member view. Expect: plays.
  • T-AUD-2 — Download the same file via its download link.
  • T-AUD-3 — Take a working audio URL, alter one character of sig, reload. Expect: 403 "Invalid or expired link". This proves the HMAC is actually enforced rather than present.

Auth

  • T-ML-1 — Send a magic link to a test address and use it. Expect: logged in.
  • T-ML-2 — Users list → activate an email account via the admin action. Then re-load that same URL. Expect: the second load is refused, not silently re-run.
  • T-EM-1 — Edit a user profile, toggle the newsletter checkbox, Update User. Expect: saved, no wp_die().
  • T-SSO-1 — Complete a Google sign-in end to end.
  • T-SSO-2 — Cancel at the provider consent screen. Expect: a readable FLOSC error notice, not a blank page.
  • T-SSO-3 — Complete an Apple sign-in with a new account, so Apple sends the user payload. Confirm the name is captured.
  • T-SSO-4 — Load any FLOSC page with ?flosc_sso_error=access_denied. Expect: the matching notice.

Navigation and display

  • T-AI-1 — AI tab → Site Index → Rebuild. Expect: "Site content index rebuilt." (this is the one path that also sets a transient, so it worked even with R-1 present).
  • T-AI-2 — The R-1 test. AI tab → Site Index → Exclude a post. Expect a notice naming the outcome. Repeat for Include, Save keywords, Reindex one. On v78 all four showed nothing. Four notices = R-1 fixed.
  • T-AI-3 — AI tab → save available providers; confirm the page returns to the same flow.
  • T-KB-1 — The R-2 test. Knowledge Base tab → click Edit on a knowledge base. Expect the editor to open on that KB. Also confirm the all/single view toggle changes the list. On v78 and earlier neither worked.
  • T-NAV-1 — Visit each Settings tab; confirm styling and controls are present, especially Flow in "all" view (portability assets load only there).
  • T-NAV-2 — Visit three shortcut slugs directly, e.g. ?page=flosc-token-management, ?page=flosc-concierge, ?page=flosc-ivr-messages. Each should redirect to its tab.
  • T-PD-1 — Open the Personality Designer from the AI tab.
  • T-PD-2 — Open ?page=flosc-personality-builder directly; expect the redirect into the designer.
  • T-TOK-1 — Token Management → toggle the filter between active and all.
  • T-CM-1 / T-CM-2 — Load a page with ?flosc_companion_handoff=1, and with ?flosc_flow_id=<flow>.
  • T-CM-3 — Load any front-end page without ?flosc_companion and confirm normal chrome; then with it and confirm embed chrome. Both directions matter — the v69 defect made every page an embed.
