## The Language: PHP

The admin pages are written in **PHP** (a programming language that runs on the server — the computer where your WordPress website lives). When someone visits your admin page, the server runs the PHP code, and the PHP code generates the HTML (the visual page) that your browser displays.

---

## The `$` Dollar Sign = "This is a variable"

In PHP, the dollar sign `$` means **"this is a variable."** A **variable** (a named container that holds a value) always starts with `$` in PHP.

- `$msg` — a variable named "msg" (short for "message")
- `$msg_name` — a variable named "msg_name"
- `$is_new` — a variable named "is_new"
- `$editing_message` — a variable named "editing_message"

The `$` is just PHP's way of saying "hey, this word is a container that holds something."

---

## The `['brackets']` = "Reach inside and grab this piece"

Square brackets `[ ]` with a word inside (called a **key**) mean: "reach inside this container and grab the piece labeled with that word."

`$msg` is not just a simple variable — it's an **array** (a container that holds multiple labeled pieces of data, like a filing cabinet with labeled folders). Each label is called a **key**, and what's in that folder is called a **value**.

So when you see `$msg['name']`, that means:
- `$msg` = the filing cabinet (the message array)
- `['name']` = open the folder labeled "name"
- The whole thing = "give me the value stored in the 'name' folder of this message"

Now I have the full picture. Here's where things stand:

---

**What the two buttons currently do:**

1. **"Save to DB"** — writes the message data to the WordPress `wp_options` table (the FLOSC flow settings). The frontend reads from this DB, so changes go live immediately.

2. **"Save & Resync to File"** — does the same DB write, then ALSO calls `flosc_auto_export_ivr_to_file()`, which writes the entire IVR message set back out to the `.md` file on disk (`ai_configuration_files/lesaep_ivr.md` or similar).

**The data flow architecture right now is:**

```
IVR .md file  ──(import)──►  WordPress DB  ──(read)──►  Frontend
                                   ▲
                            Admin edits here
                                   │
                            ──(resync)──►  IVR .md file
```

The DB is the source of truth for the live site. The `.md` file is a portable, human-readable backup/export format.

---

**Your instinct is correct: there's no good reason for two buttons.**

The original split existed during development because resync-to-file was slower and sometimes the `.md` export had bugs — so separating them let you "save safely" without risking the file export breaking your save. That was a valid development-phase safety net.

But for a shipping product, this creates confusion. A FLOSC admin shouldn't need to think about "DB vs. file." They should just click **Save**, and both happen.

**My recommendation:**

1. **Merge into one button: "Save"** — always writes to DB AND resyncs to file. One click, both targets.
2. **Keep the import direction separate** — the "Load from File" button (which already exists in your sync panel at the top of the page) stays as its own distinct action. That's the "I uploaded a new `.md` file, now load it into the DB" path.
3. **This gets you closer to the .md import vision** — the flow would be:
   - FLOSC admin writes/edits an `.md` file (or gets one from a template)
   - Uploads it to the plugin folder
   - Clicks "Load from File" → DB is populated
   - From that point on, "Save" keeps both in sync
   - The `.md` file is always a current, portable snapshot they can back up, share, or version control
