FLOSC ICON VISIBILITY ANALYSIS & FIX (v9.2.3 vs v9.7.x)
==============================

PROBLEM:
In v9.2.3, all chat and modal buttons (send, voice, close, etc.) always display their SVG icons, regardless of theme. In v9.7.x, icons sometimes disappear or become invisible, especially in overlays and on certain backgrounds.

ROOT CAUSE:
1. **v9.2.3** uses simple, direct CSS for buttons and SVGs. Button color is set with `color: white` (send) or `color: var(--flosc-primary)` (voice), and SVGs inherit this color via `stroke="currentColor"` or `fill="currentColor"`.
2. **v9.7.x** modularizes CSS, splitting button backgrounds and icon colors into separate variables (e.g., `--flosc-send-btn-bg`, `--flosc-send-btn-text`). However, the SVGs inside buttons are sometimes not explicitly styled, and their `stroke`/`fill` may not inherit the intended color due to:
   - CSS specificity issues (e.g., `.flosc_input_chat_send_button svg { ... }` missing or overridden)
   - Theme variables not being applied to SVG `stroke`/`fill`
   - Overlays or modals using backgrounds that clash with icon color

WORKING v9.2.3 CODE (CSS):
```css
.flosc_input_chat_send_button {
	background: var(--flosc-primary);
	color: white;
	/* ... */
}
.flosc_input_chat_send_button:hover {
	background: var(--flosc-primary-hover);
}
.flosc_input_chat_send_button:disabled {
	background: var(--flosc-text-muted);
}
/* SVGs use stroke="currentColor" or fill="currentColor" */
```

WORKING v9.2.3 CODE (HTML):
```html
<button class="flosc_input_chat_send_button">
  <svg ... stroke="currentColor" ...>...</svg>
</button>
```

BROKEN v9.7.x CODE (CSS):
```css
.flosc_input_chat_send_button {
	background: var(--flosc-send-btn-bg);
	color: var(--flosc-send-btn-text);
}
/* But: SVGs may not inherit color if not explicitly set! */
```

BROKEN v9.7.x CODE (HTML):
```html
<button class="flosc_input_chat_send_button">
  <svg ... stroke="currentColor" ...>...</svg>
</button>
```

In some themes/overlays, the button color is set, but the SVG icon is not visible because:
- The SVG's `stroke`/`fill` is not inheriting the button's color (due to missing or overridden CSS)
- The button background and icon color variables are mismatched (e.g., light icon on light background)
- Overlay/modal backgrounds override or obscure icon color

ROBUST FIX (v9.7.x+):
1. **Explicitly style SVGs inside all key buttons** so their `stroke` and `fill` always use the correct variable:
```css
.flosc_input_chat_send_button svg {
	stroke: var(--flosc-send-btn-text) !important;
	fill: none;
}
.flosc_input_chat_voice_button svg {
	stroke: var(--flosc-voice-btn-text) !important;
	fill: none;
}
/* For close/cancel buttons in modals/overlays: */
.modal-close svg, .copy-btn svg, .pay-btn svg {
	stroke: var(--flosc-send-btn-text, #111827) !important;
	fill: none;
}
```
2. **Ensure button backgrounds and icon colors always contrast** by setting variables in the theme layer (flosc-theme.css):
```css
:root {
	--flosc-send-btn-bg: #2563eb;
	--flosc-send-btn-text: #fff;
	--flosc-voice-btn-bg: #f3f4f6;
	--flosc-voice-btn-text: #6b7280;
}
```
3. **Test in all overlays and modals**. If overlays use a dark background, override icon color for those buttons:
```css
.modal .modal-close svg {
	stroke: #fff !important;
}
```

SUMMARY:
- v9.2.3 icons are always visible because SVGs inherit button color directly.
- v9.7.x modularization broke this inheritance; SVGs need explicit `stroke`/`fill` rules using the correct variables.
- Always set both button color and SVG stroke/fill for robust icon visibility.

ACTION: Apply these fixes to all relevant button/icon CSS in v9.7.4+ and test in every overlay/modal context.
