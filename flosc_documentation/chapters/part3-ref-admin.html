Token Management (admin/token-management.php)

Token Management controls visitor/guest/member chat wallet behavior for the selected flow. This section is the practical map for what each field does in runtime.

Design principle: FLOSC runs as a token-native economy. A floscAdmin can model total delivery economics here, not only raw AI API cost.

Runtime Debit Rule (Current Behavior)

Each chargeable AI chat turn debits the configured AI chat token cost from the active wallet.

Default behavior in this build: AI chat cost defaults to the flow value tokens_communication_tokens_per_message unless explicitly overridden by token-provider settings.

Real-cost metadata (provider billing usage and real millicents) is logged and returned in payloads for observability, while runtime control remains FLOSC-token based in this path.

Field-by-Field Meaning

Enforce Chat Token Charging: Per-flow on/off switch for charging chat turns.

Visitor Wallet Initial Amount (tokens_communication_tokens_per_message): Flow baseline wallet amount and default per-turn debit baseline.

Nominal Display Factor (tokens_nominal_millicents_per_token_*): Nominal valuation ratio for your FLOSC token economy (for example, including margin for lesson delivery and support).

Real Billing Factor (tokens_real_millicents_per_token_*): Real-cost valuation ratio used to interpret provider spend inside the FLOSC token model and reports.

Become A Guest Token Grant (guest_token_grant): Tokens granted to guest/login flow when assigned. Used in low/depleted copy placeholder math.

Low Tokens Threshold (visitor_low_token_threshold): Value at or below which low-token message can appear.

Low Tokens Message and Depleted Token Message: Per-flow copy, supports {token_grant} placeholder.

Redirect After Session End and Depleted Token Mode: Defines post-depletion capture UX and optional redirect destination.

Practical Formulas

Nominal reference millicents per message = tokens_communication_tokens_per_message × nominal_factor.

Real reference millicents per message = tokens_communication_tokens_per_message × real_factor.

Runtime token debit per chargeable turn = AI Query Cost (default baseline is tokens_communication_tokens_per_message).

Chat log telemetry per exchange = provider input/output/total tokens + actual real millicents.

Troubleshooting Quick Checks

If tokens drain too fast: verify chat charging is enabled intentionally, confirm the flow baseline value, and verify AI Query Cost has not been set higher than expected.

If low/depleted messages look wrong: confirm guest_token_grant and the {token_grant} placeholder copy.

If UI numbers look inconsistent: compare runtime wallet value with server payload token_balance.value for the same session.
