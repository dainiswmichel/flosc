## Nickname & Password Collection — Best Practices

### The Gate Logic

Check **only nickname** (`display_name` or a custom user meta like `_flosc_nickname`). If nickname exists and is not the default (not the email prefix, not "Guest", not empty), skip the prompt entirely. Password existence is implied — WordPress won't let you set one without the other during this flow.

```
User logs in via magic link
  → PHP checks: does this user have a real nickname?
  → YES → straight to app, no prompt
  → NO → JS shows nickname/password modal (dismissable)
```

### Why Not Check Password

You can't check if a WordPress user "has" a password in a meaningful way — `wp_create_user()` always sets one (even a random one for magic link users). The question isn't "do they have a password" but "did they **choose** a password." Track that with a meta flag: `_flosc_password_set_by_user = true`.

But simpler: if nickname is set to something real, they went through the prompt. One check, one field.

### The Prompt UX

1. **Show once per session maximum** — If user dismisses, don't show again until next login. Store a sessionStorage flag (`flosc_nickname_prompt_dismissed`).
2. **Dismissable but persistent** — Dismissing doesn't mean "never ask again." It means "not right now." Next magic link login, prompt reappears until they complete it.
3. **"Never ask again" = completing the fields** — Once both nickname and password are submitted and saved, the server-side meta flag prevents the prompt from ever appearing.
4. **Pre-fill email** — Show the email (non-editable) so they know which account they're setting up.
5. **Password field = optional upgrade** — Frame it as "Set a password so you can log in without email links." Not mandatory for using the app. If they skip password but enter nickname, save the nickname, set `_flosc_nickname_set = true`, and only prompt for password on future logins if desired.

### Server-Side Data Flow

```
User meta to set on completion:
  _flosc_nickname          = "their chosen name"  
  _flosc_profile_completed = true

User meta to check on login:
  if get_user_meta($user_id, '_flosc_profile_completed', true)
    → skip prompt
  else
    → include show_prompt flag in FLOSC_CONFIG
```

### What Gets Passed to JS

In `window.FLOSC_CONFIG` (built in PHP when rendering the app):
```
FLOSC_CONFIG.profileCompleted = false  // triggers JS prompt
FLOSC_CONFIG.userEmail = "their@email.com"  // pre-fill display
```

JS reads `profileCompleted`, shows the modal if `false` and `sessionStorage.flosc_nickname_prompt_dismissed` is not set.

### Edge Cases

| Scenario | Behavior |
|----------|----------|
| Magic link login, first time | Show prompt |
| User dismisses prompt | Don't show again this session. Show again next login. |
| User fills nickname only, skips password | Save nickname. Mark `_flosc_profile_completed = true`. No more prompts. |
| User fills both | Save both. Mark completed. No more prompts. |
| SSO login (Google/Facebook) | Nickname comes from OAuth profile. `_flosc_profile_completed = true` automatically. No prompt needed. |
| User already has WP account with display_name | Check if display_name is real (not email prefix). If real, mark completed, skip prompt. |
| Returning user, already completed | `profileCompleted = true` in FLOSC_CONFIG. JS never shows modal. |

### Industry Pattern

This is the "progressive profile completion" pattern. Standard in SaaS onboarding. The key principles:

1. **Don't block the experience** — Let them use the app immediately. The prompt is an overlay, not a gate.
2. **Collect at the point of value** — They just got quiz results, they're engaged. Good time to ask.
3. **Minimize fields** — Two fields max. Name + password. Nothing else.
4. **One-time collection** — Server-side flag, not client-side. Survives cleared cookies, different browsers, different devices.

        return;

    if (!$data) {
        wp_die('This link has expired or has already been used.', 'Invalid Link', ['response' => 410]);
    }

    $email = $data['email'];
    $user = get_user_by('email', $email);

    if (!$user) {
        $user_id = wp_create_user($email, wp_generate_password(12, false), $email);
        $user = get_user_by('id', $user_id);
        update_user_meta($user_id, '_flosc_auth_method', 'email_magic');
        $user->set_role('lesaep_learners'); // or whatever role you use

public function handle_update_guest_profile($request) {
    if (!is_user_logged_in()) {
        return new WP_REST_Response(['success' => false, 'message' => 'Not authenticated.'], 401);
    }
    $user_id      = get_current_user_id();
    $display_name = sanitize_text_field($request->get_param('display_name') ?? '');
    $password     = $request->get_param('password') ?? '';

    if (empty($display_name)) {
        return new WP_REST_Response(['success' => false, 'message' => 'Name is required.'], 400);
    }
    if (empty($password) || strlen($password) < 6) {
        return new WP_REST_Response(['success' => false, 'message' => 'Password must be at least 6 characters.'], 400);
    }

    $updated = wp_update_user([
        'ID'           => $user_id,
        'display_name' => $display_name,
        'nickname'     => $display_name,
    ]);
    if (is_wp_error($updated)) {
        return new WP_REST_Response(['success' => false, 'message' => 'Could not update profile.'], 500);
    }

    wp_set_password($password, $user_id);
    wp_set_auth_cookie($user_id, true);
    $flosc_token = $this->generate_flosc_auth_token($user_id);
    $this->set_flosc_auth_cookie($flosc_token);

    update_user_meta($user_id, '_flosc_profile_completed', true);

    return new WP_REST_Response(['success' => true, 'display_name' => $display_name]);
}

        'display_name' => $name,
