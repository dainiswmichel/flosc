Bug 1: Triple Backslashes in "We've sent you" Message

Symptom

After email submission, the chat displays: We\\\'ve sent you a Complimentary LeSAEp Learners Guest Access Link... — three visible backslashes before the apostrophe.

Root Cause

The message template stored in the WordPress options table has accumulated escape layers. WordPress update_option() calls maybe_serialize() which adds one layer. The admin settings page may apply wp_kses() or sanitize_text_field() on save, adding another. On retrieval, flosc_get_setting() returns the data with all layers intact because — unlike autoprompts — this message does NOT pass through the stripslashes cleanup loop.

Files Involved

admin/flosc-app.php — line 899-900 Where the message is loaded into FLOSC_CONFIG:

'guestLinkCheckEmailMessage' => flosc_get_setting('guest_link_check_email_message',
    "We've sent you a {link_name} to your email..."),

admin/flosc-app.php — line 823 The stripslashes loop that cleans autoprompts (but NOT guest link messages):

// Strip all accumulated backslash layers from corrupted data
$prev = null;
while ($prev !== $raw) { $prev = $raw; $raw = stripslashes_deep($raw); }

assets/js/flosc-app.js — line 4643 Where JS uses the config value:

const checkEmailMsg = (this.config.guestLinkCheckEmailMessage || "We've sent you a...")
    .replace('{link_name}', this.config.guestLinkName || '...');

Fix

Apply the same stripslashes treatment to the guest link message settings when loading them into FLOSC_CONFIG. In admin/flosc-app.php, where guestLinkCheckEmailMessage and guestLinkWelcomeMessage are retrieved, wrap with wp_unslash():

// BEFORE (buggy):
'guestLinkCheckEmailMessage' => flosc_get_setting('guest_link_check_email_message', "We've sent you..."),

// AFTER (fixed):
'guestLinkCheckEmailMessage' => wp_unslash(flosc_get_setting('guest_link_check_email_message', "We've sent you...")),

Apply the same wp_unslash() to guestLinkWelcomeMessage, guestLinkName, and guestLinkProfileConfirmMessage — any setting that may contain apostrophes.

Alternative (database-level fix): If the corruption is already baked into the stored option value, also run a one-time cleanup: update_option('flosc_settings', wp_unslash(get_option('flosc_settings'))) from WP-CLI or a temporary admin action.

Symptom

How Recordings Are Stored

During magic link login, the handler at flosc.php:2037 calls one of two paths:

  1. Path A — DigitalOcean pull (pull_session_from_do(), line 8564): Downloads audio from https://api.lesaep.com/session/{session_id}/audio/{n} → saves to wp-content/uploads/flosc-users/{user_id}/sessions/{session_id}/phrase-{n}.webm
  2. Path B — Browser quiz data (store_browser_quiz_data(), line 8431): Moves files from flosc-temp/{temp_id}/ → flosc-users/{user_id}/sessions/{temp_id}/

How Playback Is Built

Likely Causes (ranked by probability)

  • 3. AJAX proxy permission check: The proxy at line 10245 checks user permission. If the logged-in user is viewing their own profile but the permission check expects admin, playback fails silently.
