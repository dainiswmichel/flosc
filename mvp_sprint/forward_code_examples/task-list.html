Task 2: Fix All AI Hallucinations — Make AI a True FLOSC Flow Facilitator Essential

Observed Failures

On 2026-03m-16d testing, the chatbot on lesaep.com exhibited the following failures — intermittently, not consistently:

  • Responded: "Are you interested in learning French, or do you have questions about the FLOSC lessons?" — pivoting to French on a Standard American English pronunciation site
  • Expanded the FLOSC acronym incorrectly and insisted on the wrong expansion
  • Expanded the LeSAEp acronym incorrectly
  • Invented lesson content rather than routing users to existing configured WordPress posts

The behavior is intermittent, which means the problem is not only "AI ignoring instructions" — it also includes cases where instructions were likely missing, incomplete, or not delivered correctly. Writing better text instructions alone will not fix this. The fix must be largely mechanical.

How the Context System Works Now

The live AI context system is class-flosc-chatpack.php — not class-ai-chat-dispatch.php. The chatpack assembles everything sent to the AI.

On the First Message of a Session

build_full_chatpack() sends a 7-section system prompt:

SectionContents
HeaderFLOSC-HASH (permanent install ID) + FLOSC-SESSION (session ID), both using MichelTimestamps
1. IdentityFLOSC definition, product name + tagline, AI persona, 5 ABSOLUTE RULES (acronyms, no fabrication, stay in lane, content access, honesty over helpfulness)
2. WordPress EnvironmentSite name, URL, timezone, locale, FLOSC version
3. User IdentityAccess level, name, quiz scores, correct/missed items, weakest sounds, progress flags
4. Flow ContextCurrent phase, all 5 FLOSC phase descriptions, phase-specific behavioral instructions
5. Knowledge BaseAdmin corrections, admin praise, all .md files from ai_configuration_files/ (access-filtered, truncated at 3,000 chars each)
6. IVR GuidanceIf an IVR message matched — the scripted content the AI should humanize (strongest constraint available)
7. Conversation RulesPair number, anti-repetition rules, FACTUAL GROUNDING reminder at end (recency bias placement)

On Every Subsequent Message

build_followup_chatpack() sends only:

  • Session reference (FLOSC-HASH, FLOSC-SESSION, pair number, phase)
  • Phase change notice (only if phase changed)
  • State updates if a transition occurred (quiz completed, logged in, purchased)
  • IVR guidance (if matched)

All 5 absolute rules, all acronym definitions, all grounding reminders — gone after message one. The AI operates on memory alone from message 2 onward. When memory drifts, training fills the gap — and training is wrong.

IVR Matching

Before invoking the AI at all, handle_chat() checks whether the user's message matches a scripted IVR response. If it matches, the scripted content is passed as ivr_guidance and the AI is asked to humanize it — very little room to fabricate. The hallucination risk is highest when no IVR matches and the AI generates freely.

Knowledge Base Loading

load_knowledge_files() skips any file with ivr in the filename. This means lesaep_ivr.md — which contains the richest LeSAEp product knowledge, lesson descriptions, and IVR message content — is never loaded into the AI knowledge base. Each file is also hard-truncated at 3,000 characters.

Conversation History — Per-Session Context Building

Every API call includes the last 10 message pairs as conversation history alongside the system prompt. The system IS building context per session — the AI can see prior exchanges. Logged-in users: loaded from DB via FLOSC_Session_Manager at full length (class-flosc-chatpack.php — line 146). Visitors: sent from JavaScript localStorage, each message truncated to 500 characters server-side (flosc.php — line 4557).

Critical distinction: Conversation history carries what was said — not what the system prompt instructed. The FLOSC and LeSAEp definitions from the full chatpack are in the message 1 system prompt. Unless the AI explicitly restated "FLOSC stands for Freeline..." in one of its responses, those definitions are invisible to the AI on messages 2 through 10. History carries session context from exchanges; it does not carry system prompt rules.

State Transitions — Already Handled

Quiz completion, login, and purchase transitions already trigger state update notices in the follow-up chatpack. The quiz score and weakest sounds are included in Section 3 of the full chatpack.

RAG Code Path — Completely Unguarded

flosc.php — line 4793 build_rag_system_prompt() bypasses the entire chatpack system. It reads only ai_identity_name and ai_identity_role from settings. No absolute rules, no acronym definitions, no phase instructions, no factual grounding.

Temperature

Default is 0.7 across all three AI provider call sites in class-ai-chat-dispatch.php (lines 810 and 1009). 0.7 is a creative setting — it increases the probability of plausible-sounding but fabricated responses.

Logging

None exists. When a hallucination is reported, there is no record of what system prompt the AI received, what message number the session was on, or what the AI returned.

Specific Gaps — What Is Broken

Gap 1 — Mid-session drift (highest risk)

After message 1, the follow-up system prompt contains no rules, no acronym definitions, no grounding reminders. The AI does receive conversation history (last 10 pairs), which provides session context — but conversation history carries what was said, not what the system prompt instructed. The fixed definitions (FLOSC, LeSAEp) live only in message 1's system prompt. Unless the AI restated them verbatim in a prior response, they are absent from the AI's authoritative context on messages 2 through 10. Training fills the gap — and training is wrong. This is the most likely cause of intermittent hallucinations.

Gap 2 — lesaep_ivr.md excluded from knowledge base

load_knowledge_files() skips files with ivr in the filename. The LeSAEp product knowledge — lesson descriptions, product facts — is in lesaep_ivr.md and never reaches the AI's knowledge base section. The AI has no authoritative lesson inventory to reference.

Gap 3 — KB files truncated at 3,000 characters

A lesson catalog covering 44–50 LeSAEp sounds will be cut off mid-entry. The AI gets an incomplete picture of what lessons exist and may fabricate the rest.

Gap 4 — RAG path has no grounding

build_rag_system_prompt() bypasses everything. No rules, no definitions, no phase instructions. Full fabrication risk on this code path.

Gap 5 — No logging

Impossible to diagnose intermittent hallucinations without knowing what was sent and received. Every incident is a guess.

Gap 6 — Temperature 0.7

Rewards creative generation. Wrong default for a precision facilitator role.

Gap 7 — No mechanical output enforcement

Every constraint relies on the AI choosing to comply. Nothing intercepts the output. If the AI generates a wrong acronym expansion, it reaches the user unchallenged.

Gap 8 — No admin visibility into risk conditions

Empty product name, empty tagline, high temperature — the admin has no warning that these conditions exist and increase hallucination risk.

Gap 9 — Visitor conversation history truncated to 500 characters per message

flosc.php — line 4557: substr($msg['content'], 0, 500). A detailed AI response explaining a phonetic concept can be cut in half in the history. The AI sees a truncated version of its own prior response and loses context it established earlier in the session. Logged-in users are not affected — their history is loaded from DB at full length. Visitors are the highest-risk population (freeline phase, no account) and their session history is the least reliable.

Session Context Architecture — The Correct Model

Stateless vs. Stateful — and Why It Matters

AI language model APIs are stateless — every call is independent, the model has no memory between calls. The opposite is stateful, where the server maintains session memory between calls (like a traditional WebSocket or server-side session). Stateful AI systems exist (MemGPT, fine-tuned models) but are expensive, complex, and not appropriate for a funnel facilitator at this stage.

All major providers — OpenAI, Anthropic, Google Gemini, xAI, Mistral — are stateless. This is not a provider limitation; it is the architecture of large language models. Switching providers would not change this. There is no AI service that natively remembers between API calls.

The FLOSC session history approach (DB for logged-in users, localStorage for visitors, last 10 pairs sent with every call) IS the industry-standard pattern. Every chatbot — ChatGPT, Claude.ai, Gemini — works this way. You are in full control of what context the AI receives, which is an advantage: it is the mechanism that allows you to prevent hallucination.

What "stateful-ish" options actually exist (as of mid-2026):

FLOSC controls all context.Strong fit — Fix 13. This is the architecture the system was designed assuming. Full context maintained throughout session at low per-message cost.

The architecture verdict: FLOSC must own quiz results, funnel phase, lesson mapping, and hard constraints — that does not change regardless of provider. The question is how the AI context is maintained across a session. Two viable paths: OpenAI Responses API (send full chatpack once on message 1, chain via previous_response_id — OpenAI holds context, FLOSC still injects state updates when phase/quiz changes) and Anthropic prompt caching (send full chatpack every message, ~10% token cost on static cached sections). Both solve mid-session drift. The OpenAI Responses API path has a lower per-message token footprint for sessions where context doesn't change. Fix 13 implements the Responses API path; provider comparison test confirms which is more reliable in practice.

The cost tradeoff that created the hallucination problem: The current design paid for 5,000 tokens on message 1 and "coasted" on conversation history for messages 2+. But conversation history carries what was said, not what the system prompt instructed. Rules, definitions, and identity from message 1 are gone by message 2. The system optimized for token cost and produced mid-session hallucinations as a result.

Approach10-message session
Current: full chatpack msg 1 + 100-token follow-ups~5,900 tokens — definitions gone after msg 1, hallucinations follow

Full chatpack msg 1 + Anthropic prompt caching msgs 2–10~9,500 tokens — full context every message, ~10% cost on cached sections

Anthropic prompt caching — mark static chatpack sections with "cache_control": {"type": "ephemeral"}. Message 1 pays full tokens. Messages 2–10 pay ~10% on those sections. The AI receives the full chatpack on every message for roughly the same cost as the current broken approach.

OpenAI Responses API — closer to the original intended architecture. The current FLOSC OpenAI path uses Chat Completions (/v1/chat/completions) and resends the full messages array on every call. The Responses API (/v1/responses) works differently: send full context once, OpenAI stores the response (store: true is their default), subsequent calls send only previous_response_id + the new message and OpenAI reconstructs context server-side. This is what a reasonable designer would have assumed the API did in the first place. Supporting it requires a new provider path in class-ai-chat-dispatch.php — different endpoint, different request format, session management for response_id. This is a separate implementation track from the chatpack fixes but architecturally the right direction if OpenAI is the primary provider.

Fix 4 (anchor lines in every follow-up) is not invalidated by either of these. It is a provider-agnostic safety net that works regardless of which call path is active. It costs nothing and ensures the two fixed definitions are always in the system prompt regardless of caching behavior or API version.

The system already builds context per session via conversation history (last 10 pairs sent on every API call). The AI is not starting from scratch on each message. The conversation history carries what was said — topics discussed, guidance given, lessons referenced.

The actual problem: the system prompt oscillates instead of maintaining a consistent anchor.

  • Message 1 system prompt: ~5,000 tokens (everything: identity, rules, user profile, all KB files)
  • Messages 2+ system prompt: ~100 tokens (session reference only)

The AI gets maximum context at message 1 (when there is no conversation yet) and minimum context at messages 10+ (when the conversation is richest). This is backwards.

The correct model — three distinct layers:

LayerWhat Goes ThereWhen Sent
AnchorDefinitions, role, 5 rules, current phaseEvery message — full and follow-up
Session stateUser profile, quiz results, access level, phase changesMessage 1 full + follow-up when changed
Conversation historyPrior exchanges — what was said and answeredEvery message (last 10 pairs — existing code)

What this means for KB and lesson content: Loading all 44+ lessons into the message 1 system prompt front-loads content the AI may never use. Better: a KB overview (product, subject, lesson count) in the anchor layer; specific lesson content fetched when that lesson is mentioned. Dynamic per-lesson injection is a next-sprint enhancement. For MVP: Fix 4 (anchor definitions) + Fix 5 (lesaep_knowledge.md overview) + Fix 7 (KB size limit) are sufficient.

What Fix 4 actually does in this model: It is not resending everything. It moves the two fixed definitions from message 1's system prompt (where they decay by message 10) into the Anchor layer (where they are always present). Lesson content stays in conversation history. This is the minimum correct architecture.

The Role of the AI — What It Should and Should Not Do

The AI is a facilitator of the floscAdmin-configured FLOSC flow. It is not a free-form assistant. It operates within the configured flow, the subject matter of the flow (LeSAEp = Standard American English pronunciation), and the user's current phase.

Within those bounds, the AI should be genuinely useful: explain phonetic concepts (voiced, unvoiced, pulmonic, retroflex), guide users to the right lessons, connect Lesson 17 and Lesson 35 for a user who needs both, offer practice ideas. That is valuable and correct behavior.

Two things it must never do:

  1. Fabricate fixed facts. FLOSC = Freeline, Login, Offer, Sale, Content — always, never any other expansion. LeSAEp = Learn Excellent Standard American English Pronunciation — always, never any other expansion. These are non-negotiable and cannot be invented or varied.
  2. Substitute another subject. A user at LeSAEp who has paid for SAE lessons is owed SAE content — not French lessons, not generic English content, not anything the AI invented.

Fix 3 — Response Validation Layer

includes/class-ai-chat-dispatch.php — new method, called from get_response()

A new validate_ai_response($response) method that runs on every AI response before it is returned or cached. Detects wrong acronym expansions using regex and corrects them in the output. Requires no AI cooperation — it intercepts the output regardless of what the AI decided. Logs every correction made.

private function validate_ai_response($response) {
    if (empty($response)) return $response;
    $log = [];

    // Correct wrong FLOSC expansions
    if (preg_match('/FLOSC\s+stands?\s+for\b/i', $response)) {
        if (!preg_match('/Freeline.*Login.*Offer.*Sale.*Content/i', $response)) {
            $orig = $response;
            $response = preg_replace(
                '/FLOSC\s+stands?\s+for[^.!?\n]*/i',
                'FLOSC stands for Freeline, Login, Offer, Sale, Content',
                $response
            );
            if ($response !== $orig) $log[] = 'Corrected wrong FLOSC expansion';
        }
    }

    // Correct wrong LeSAEp expansions
    if (preg_match('/LeSAEp\s+stands?\s+for\b/i', $response)) {
        if (!preg_match('/Learn\s+Excellent\s+Standard\s+American\s+English\s+Pronunciation/i', $response)) {
            $orig = $response;
            $response = preg_replace(
                '/LeSAEp\s+stands?\s+for[^.!?\n]*/i',
                'LeSAEp stands for Learn Excellent Standard American English Pronunciation',
                $response
            );
            if ($response !== $orig) $log[] = 'Corrected wrong LeSAEp expansion';
        }
    }

    if (!empty($log)) {
        $entries = get_option('flosc_validation_corrections', []);
        $entries[] = ['time' => current_time('mysql'), 'corrections' => $log];
        update_option('flosc_validation_corrections', $entries);
    }

    return $response;
}

Call $response = $this->validate_ai_response($response); in get_response() before caching and returning.
